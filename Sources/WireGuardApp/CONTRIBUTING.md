## Code of Conduct

By participating in this project, you agree to abide by the [Code of Conduct](CODE_OF_CONDUCT.md). Please read it to understand the expectations for behavior when contributing to WireGuardApp.

## How to Contribute

There are several ways you can contribute to WireGuardApp:

- Reporting bugs and issues
- Suggesting new features and enhancements
- Submitting pull requests with code improvements
- Improving documentation
- Writing tests

## Reporting Issues

If you encounter any issues or bugs while using WireGuardApp, please report them by creating a new issue in the [GitHub Issues](https://github.com/WireGuardApp/issues) section. Provide as much detail as possible, including steps to reproduce the issue, the expected behavior, and any relevant logs or screenshots.

## Submitting Pull Requests

To submit a pull request, follow these steps:

1. Fork the repository and create a new branch from the `main` branch.
2. Make your changes in the new branch.
3. Ensure that your code follows the [Coding Guidelines](#coding-guidelines) and includes appropriate tests.
4. Commit your changes with a clear and descriptive commit message.
5. Push your changes to your forked repository.
6. Create a pull request from your branch to the `main` branch of the WireGuardApp repository.
7. Provide a detailed description of your changes in the pull request, including the motivation and any relevant context.

## Coding Guidelines

Please follow these coding guidelines when contributing to WireGuardApp:

- Write clean, readable, and maintainable code.
- Follow the existing code style and conventions.
- Add comments to explain complex logic and code sections.
- Ensure that your code is properly formatted and linted.
- Write unit tests for new features and bug fixes.

## Testing

WireGuardApp uses unit tests to ensure the functionality and stability of the codebase. When submitting a pull request, make sure to include appropriate tests for your changes. Run the tests locally to verify that they pass before submitting your pull request.

## Documentation

Good documentation is essential for the success of any project. If you make changes to the code that affect the usage or behavior of WireGuardApp, please update the relevant documentation accordingly. This includes updating comments, README files, and any other relevant documentation files.

## Continuous Integration

WireGuardApp uses continuous integration (CI) to automatically run tests and checks on each commit. This helps ensure that the codebase remains stable and free of errors. When submitting a pull request, make sure that your changes pass all CI checks. If any issues are found, address them before merging your pull request.
